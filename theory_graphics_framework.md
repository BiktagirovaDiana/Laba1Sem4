# Теория для защиты графического фреймворка

---

## 1. Гамма-коррекция (Gamma Correction)

### Что такое гамма?

Мониторы с ЭЛТ (электронно-лучевой трубкой) имеют нелинейный отклик: зависимость выводимой интенсивности света от входного напряжения описывается **экспоненциальной кривой** — это и называется **гаммой**.

Типичная гамма монитора = **2.2**: пиксель с интенсивностью 50% излучает лишь **~22%** света, а не 50%.

### Три ключевые кривые

| Кривая | Формула | Назначение |
|--------|---------|-----------|
| Линейная | `F(x) = x` | Идеальный линейный отклик |
| Гамма-кодирование (sRGB) | `F(x) = pow(x, 0.45)` | Запись в файл/буфер, ~1/2.2 |
| CRT Gamma | `F(x) = pow(x, 2.2)` | Отклик монитора |

Если применить обратную кривую гаммы 2.2 к кривой гаммы 2.2 — получим исходное изображение.

### Почему не хранить в линейном пространстве?

Человеческий глаз лучше воспринимает оттенки тёмного. Гамма 2.2 даёт **больше кодовых значений для тёмных цветов**, что является схемой нелинейного сжатия, почти точно совпадающей с особенностями человеческого зрения.

### Что такое sRGB?

**sRGB (standard Red Green Blue)** — цветовое пространство, созданное HP и Microsoft в 1996 году. Современные мониторы автоматически применяют коррекцию sRGB к цветам перед их отображением. Обязательно в DirectX начиная с версии 10 (2008).

Кривые гаммы 2.2 и sRGB выглядят очень похоже, но sRGB — более точный стандарт.

### Гамма-кодирование и декодирование

- **Гамма-кодирование** — преобразование из линейного пространства в гамма-пространство (перед сохранением в файл или выводом на экран).
- **Декодирование** — обратное преобразование в линейное пространство перед работой со значениями изображения.

### Гамма-коррекция в DirectX

Для работы с гамма-коррекцией используются форматы, оканчивающиеся на `_SRgb`:
- Для **SRV** — значения из текстуры автоматически переводятся в линейное пространство при сэмплировании.
- Для **RTV** (бэк-буфер) — значения преобразуются в пространство sRGB при записи.

### Правила применения

- Диффузные текстуры **уже скорректированы по гамме** — загружать их нужно с флагом sRGB формата.
- Карты нормалей, карты освещения, карты смещения и другие данные, не представляющие цвет — **не применять** гамма-преобразование.
- Использовать формат sRGB **только для финального RTV**, отображаемого на экране. Для промежуточных RTV — нет.

### Как обнаружить ошибки гамма-коррекции?

- Дальние мип-мап текстуры выглядят **заметно темнее** крупных.
- Цветовые тона изменяются при изменении яркости освещения.
- Компенсация качества с помощью дополнительных источников света или трюков в шейдерах.

## 2. Color Banding и Dithering

### Color Banding (Цветовые полосы)

Артефакт, при котором **чётко видна граница** между областями одного цвета. Особенно заметен на однообразных поверхностях (небо). Может усиливаться при нелинейных преобразованиях и низкой точности форматов.

**Пример возникновения:**
При рендеринге в `DXGI_FORMAT_R8G8B8A8_UNORM` с последующей гамма-коррекцией (pow 1/2.2): значение текстуры 1 переходит в экранное значение 21 — значения 1–20 **не используются**, что вызывает потерю точности. Решение: использовать `DXGI_FORMAT_R16G16B16A16_FLOAT`.

**Два вида полос и их решения:**
- Потеря точности → **увеличить разрядность** формата хранения.
- Ограниченная точность экрана → **дизеринг (dithering)**.

### Dithering

Способ рисования градиентов путём варьирования количества пикселей двух соседних цветов. Работает только для больших (по размеру) градиентов, не зависит от точности.

**Реализация для 8-битного буфера:**
1. Вычислить `v' = 255 · v`
2. `v0 = floor(v')`, `v1 = v0 + 1`, `dv = v' − v0`
3. Если значение маски дизеринга < `dv` → писать `v1/255`, иначе `v0/255`
4. Применять для каждого канала (R, G, B) отдельно

```hlsl
float3 color = ...;
float3 c = color * 255.0f;
float3 c0 = floor(c);
float3 c1 = c0 + float3(1.0f, 1.0f, 1.0f);
float3 dc = c - c0;
float threshold = ditherMask.Sample(pointSampler, texCoord);
color = c0 / 255.0f;
if (dc.r > threshold) color.r = c1.r / 255.0f;
if (dc.g > threshold) color.g = c1.g / 255.0f;
if (dc.b > threshold) color.b = c1.b / 255.0f;
```

**Маска дизеринга** — одноканальная текстура с пороговыми значениями для каждого пикселя. Обычно небольшого размера (16×16), циклически повторяется по экрану.

**Виды масок:**
- **Байера** — быстро генерируется, могут быть видны артефакты из-за регулярности.
- **Void-and-cluster** — использует синий шум, лучше распределение пикселей.

### Screen-Door Transparency

Дизеринг используется как быстрый аналог прозрачности: если значение альфа-канала больше значения из маски — пиксель рисуется, иначе отбрасывается (`clip`). Не требует сортировки объектов по глубине.

```hlsl
float4x4 thresholdMatrix = {
    1.0/17.0,  9.0/17.0,  3.0/17.0, 11.0/17.0,
   13.0/17.0,  5.0/17.0, 15.0/17.0,  7.0/17.0,
    4.0/17.0, 12.0/17.0,  2.0/17.0, 10.0/17.0,
   16.0/17.0,  8.0/17.0, 14.0/17.0,  6.0/17.0
};
clip(alpha - thresholdMatrix[pos.x % 4][pos.y % 4]);
```

## 3. Post-Processing (Постобработка)

Операции, выполняемые с уже визуализированным изображением.

**Цели:**
- Симуляция эффектов камеры
- Моделирование HDR-эффектов
- Художественная настройка цвета и общего вида
- Расчёт распределения света в пространстве
- Anti-aliasing

**Входные данные:** визуализированное изображение в линейном пространстве + G-буфер.  
**Выходные данные:** изображение готовое к отображению на мониторе.

## 4. HDR и Tone Mapping

### LDR vs HDR

- **LDR (Low Dynamic Range):** форматы `xxx_UNorm`, значения [0.0, 1.0].
- **HDR (High Dynamic Range):** форматы `xxx_FLOAT` (16+ бит на канал), значения могут превышать 1.

При накоплении освещения значения могут превысить 1 — без HDR яркие детали **обрезаются** (насыщенность/saturation).

### Tone Mapping (Тональное отображение)

Процесс сопоставления HDR-значений с LDR для вывода на экран.

**Рейнхард (простейший):**
```hlsl
float3 ldr = hdr / (hdr + 1.0f);
```

**С экспозицией:**
```hlsl
float3 ldr = float3(1,1,1) - exp(-hdr * Exposure);
```
Параметр `Exposure` имитирует выдержку камеры — низкая при дневном свете, высокая ночью.

### Eye Adaptation (Адаптация глаза)

Человеческий глаз адаптируется к разной яркости. Реализация:
1. Вычислить среднюю яркость текущего кадра.
2. Взять яркость предыдущего кадра.
3. Интерполировать с разными скоростями для увеличения и снижения яркости:
```hlsl
float adaptedLuminance = lerp(previousAvgLuminance, currentAvgLuminance, adaptationSpeedFactor);
```

**Простой способ вычислить среднюю яркость:**  
Нарисовать HDR-буфер в RTV 1024×1024, сгенерировать мип-мапы через `GenerateMips` — последний мип (1×1) хранит среднюю яркость.

Формула яркости: `luminance = dot(HDRcolor, float4(0.299, 0.587, 0.114, 0))`  
или `(0.2126, 0.7152, 0.0722)`.

## 5. Bloom (Свечение)

Эффект постобработки, воспроизводящий артефакт видеокамеры: утечку света от ярких пикселей к соседним более тёмным.

**Этапы:**
1. Выделить яркие пиксели (luminance > 1.0 или заданного порога):
```hlsl
bloomColor = luminance > 1.0f ? HDRColor : float3(0,0,0);
```
2. Размыть результат (Gaussian Blur).
3. Добавить к HDR перед тональным отображением или к LDR после — с некоторым весом.

## 6. Gaussian Blur

Фильтр размытия, использующий гауссову функцию.

**Ключевое свойство:** 2D ядро гауссова фильтра **разделимо** — его можно выразить как внешнее произведение двух векторов. Это позволяет разбить фильтрацию на два прохода: горизонтальный и вертикальный.

**Реализация на PS:**
```hlsl
float4 color = Source.SampleLevel(..., uv, 0) * Weights[0];
float2 texelSize = float2(1.0f/width, 0.0f); // или (0, 1/height)
for (int i = 1; i <= 3; i++) {
    color += Source.SampleLevel(..., uv + texelSize*i, 0) * Weights[i];
    color += Source.SampleLevel(..., uv - texelSize*i, 0) * Weights[i];
}
```

**Реализация на CS** (вычислительный шейдер):  
Использует `groupshared` память (TLS) для кэширования строки пикселей внутри группы. Синхронизация через `GroupMemoryBarrierWithGroupSync()`.

## 7. Camera Effects (Эффекты камеры)

Цель — имитация поведения реальной камеры/сенсора.

### Lens Flares (Блики объектива)
Результат отражений в системе объектива. Реализуются как спрайты вдоль линии через центр экрана, с прозрачностью зависящей от яркости источника.

### Vignetting (Виньетирование)
Снижение яркости пикселей, удалённых от центра. Реализация: затемнять пиксели в зависимости от расстояния до центра экрана.

### Chromatic Aberration (Хроматическая аберрация)
Сдвиг каналов R, G, B на разное расстояние от центра экрана при выборке из текстуры. Имитирует оптические искажения дешёвых камер; часто используется для эффекта повреждения игрока.

### Noise / Grain (Шум/зернистость)
Добавление случайного шума к изображению. Зернистость должна быть **динамической** — меняться каждый кадр.

## 8. Color Correction (Цветокоррекция)

Изменение цветовой гаммы кардинально влияет на настроение сцены.

**Workflow с цветовым кубом (LUT):**
1. Сделать скриншот игры и добавить к нему нейтральный цветовой куб.
2. Загрузить в Photoshop, применить цветокоррекцию.
3. Извлечь изменённый куб.
4. Использовать изменённый куб для выборки новых цветов (после тонального отображения).

---

## 9. Depth of Field (Глубина резкости)

**Circle of Confusion (COC)** — размер кружка нерезкости для данного пикселя. Вычисляется из карты глубины с параметрами линзы.

**Методы реализации:**
- **Poisson disc blur** — функция распределения, COC определяет масштаб.
- **Multi-passed diffusion** — каждый пиксель обновляется по градиенту COC, повторяется 10–30 раз.
- **Separable diffusion**
- **Summed-area table**

**Другие подходы в растеризаторе:**
- Рендеринг с нескольких точек обзора + усреднение.
- Разбиение на слои, раздельный рендеринг, размытие каждого слоя.
- Замена каждого пикселя дисковым спрайтом с размером = COC.
- Несколько буферов с разным размером размытия + выбор нужного по пикселю.

## 10. Screen Space Reflections (SSR)

Отражения на основе данных экранного пространства:

1. Из карты глубины определить **начало луча**.
2. Из нормали и направления взгляда вычислить **зеркальное направление**.
3. Шагать вдоль луча по одному пикселю.
4. Найти пиксель, где глубина сцены ближе, чем луч — предыдущий пиксель является точкой пересечения.

Для ускорения используется **Pixel Stride** (шаг в пикселях), но уменьшает качество.

## 11. God Rays (Объёмное рассеяние света)

Имитация объёмного рассеяния — видимых лучей от источника света.

**Этапы реализации:**

**Проход рассеяния (Light Scattering Pass):**
- Отрисовать сцену чёрным, кроме источника света (billboard или диск).
- Или использовать значения глубины из G-буфера для рендеринга источника.

**Проход God Rays:**
1. Нарисовать full-screen quad.
2. Передать положение источника света в пикселях в шейдер.
3. От каждого пикселя пустить луч в сторону источника.
4. Сэмплировать карту рассеяния вдоль луча с затуханием (decay) и суммировать:

```hlsl
float2 deltaTexCoord = (tc - lightPositionOnScreen) / NUM_SAMPLES * density;
float illuminationDecay = 1.0;
for (int i = 0; i < NUM_SAMPLES; i++) {
    tc -= deltaTexCoord;
    float4 sample = LightMap.Sample(sampler, tc) * weight;
    sample *= illuminationDecay;
    color += sample;
    illuminationDecay *= decay;
}
```
5. Добавить рассчитанный свет к цвету сцены.

**Tessellated God Rays (продвинутый метод):**
1. Генерировать сетку в near plane.
2. Тесселировать.
3. Выбирать из карты теней и смещать вершины.
4. Добавлять «крышку».
